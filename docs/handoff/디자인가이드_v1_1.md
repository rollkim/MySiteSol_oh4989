# 지도형 부동산 중개사무소 홈페이지 — 디자인 가이드 v1

> **용도**: 이 문서를 Claude에 붙여넣고 디자인 시안(HTML 프로토타입)을 요청하기 위한 브리프.
> 문서 맨 아래 §10의 프롬프트를 이 문서와 함께 그대로 전달하면 된다.
> **참고 기준**: myoungyul.com(명율공인중개사)의 화면·메뉴 구성과 디자인 토큰을 계승 기반으로 삼고, 네이버 부동산 구버전 PC 레이아웃을 지도 화면의 구조 레퍼런스로 삼는다.

## 1. 프로젝트 정의

| 항목 | 내용 |
|---|---|
| 무엇 | 단일 공인중개사무소용 매물 사이트 (지도형 검색 중심) |
| 의뢰인 | 네이버 블로그를 활발히 운영하는 중개사무소 대표 |
| 주 유입 경로 | 네이버 블로그 → 사이트 매물 링크, 네이버/구글 검색, 파워링크 |
| 이 사이트의 단 하나의 임무 | **지도에서 매물을 찾아 전화·문의로 전환시키는 것** |
| 방문자 | 40~60대 실수요자 비중 높음. 모바일 비중 70% 이상 가정 |
| 회원 정책 | **비회원 전용 확정.** 로그인 UI는 관리자에게만 존재한다 |
| 콘텐츠 | **동영상을 적극 활용.** 매물 영상이 사진과 대등한 설득 수단이다 |
| 의뢰인 성향 | 블로그를 직접 운영하며 시각 콘텐츠 감각이 있는 분. **템플릿 티가 나면 바로 걸린다** |

### 명율 대비 포지셔닝

| 축 | 명율 (기존) | 이번 사이트 (신규) |
|---|---|---|
| 매물 성격 | 산업용 (공장·창고·토지) | 주거·상가 중심 |
| 탐색 방식 | **목록형** 중심 | **지도형** 중심 + 목록 병행 |
| 톤 | 무게감·신뢰 (딥 네이비) | 신뢰 유지 + 더 가볍고 날렵하게 |

> **핵심**: 명율의 신뢰감 있는 톤은 유지하되, 지도가 화면의 주인공이 되도록 UI 크롬(chrome)을 명율보다 훨씬 얇게 만든다.

## 2. 메뉴 구성 (IA)

### 2-1. 명율에서 계승하는 구조

명율의 골격은 `홈 → 매물 카테고리별 목록 → 매물 상세 → 문의` + `회사소개` + `매물 등록 의뢰` + `관리자 백오피스`다.
이번 사이트는 여기에 **지도 검색**을 최상위로 끌어올린다.

> ⚠️ 명율의 실제 GNB 라벨과 다르면 아래 표를 실제 라벨로 교체할 것.

### 2-2. PC 글로벌 내비게이션

```
[로고]   지도로 찾기 | 매물 목록 | 매물 등록 의뢰 | 중개사무소 소개 | 문의        ☎ 031-000-0000
```

- **지도로 찾기**를 첫 번째에 두고 시각적으로 가장 강하게 처리 (이 사이트의 정체성)
- 우측 전화번호는 항상 노출. 클릭 시 `tel:` 링크
- 매물 목록에는 하위 필터 진입점(거래유형·건물유형) 노출

### 2-3. 모바일 하단 탭바 (5개 고정)

```
┌──────┬──────┬──────┬──────┬──────┐
│ 지도  │ 목록  │ 관심  │ 문의  │ 더보기│
└──────┴──────┴──────┴──────┴──────┘
```

- 앱 다운로드 없이 웹에서 앱 같은 조작감 확보가 목표
- **관심(찜)** 은 로그인 없이 localStorage 기반으로 동작하는 것으로 가정
- 더보기: 중개사무소 소개 / 매물 등록 의뢰 / 블로그 / 이용약관·개인정보 / 관리자 로그인

## 5. 디자인 방향

### 5-1. 컨셉 한 줄

> **"지도가 주인공이고, UI는 지도 위에 놓인 얇은 도구다."**

지도 자체가 이미 색·선·텍스처로 가득한 캔버스다. 그래서 이 사이트의 디자인은 **더 그리는 쪽이 아니라 덜어내는 쪽**으로 승부한다. 대신 지도 위에 떠 있는 소수의 요소(마커, 필터 칩, 바텀시트, CTA)에만 개성을 집중시킨다.

### 5-2. 컬러 (확정 — 사장님 제안 네이비 톤)

의뢰인이 네이비 톤을 직접 선택했다. 명율의 딥 네이비 계열을 잉크와 액센트 양쪽에 쓰되, 단계를 나눠 단조로움을 피한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--ink` | `#0F1C2E` | 텍스트, 마커 배경, 헤더 |
| `--ink-70` | `#3A4A5E` | 보조 텍스트 |
| `--ink-40` | `#8894A3` | 캡션, 비활성 |
| `--line` | `#E4E8EE` | 구분선 (1px, 지도 위에서는 사용 금지) |
| `--surface` | `#FFFFFF` | 카드·시트 |
| `--surface-alt` | `#F5F7FA` | 섹션 배경 |
| `--accent` | `#1F4E8C` | **브라이트 네이비**. CTA, 선택 상태, 활성 필터 |
| `--accent-soft` | `#E7EEF7` | 액센트 배경, 선택 칩 배경 |
| `--price` | `#0F1C2E` | 가격 텍스트 (액센트로 쓰지 않는다) |
| `--alert` | `#C0392B` | 거래완료, 오류 |

**네이비 2단 구조의 이유** — 잉크(#0F1C2E)와 액센트를 같은 색으로 쓰면 "지금 눌려 있는 것"과 "그냥 글자"가 구분이 안 된다. 액센트는 같은 네이비 계열에서 명도·채도를 올린 #1F4E8C로 분리해, 단색 팔레트의 통일감을 유지하면서 인터랙션 상태를 읽을 수 있게 한다. 마커 선택 상태도 `--accent`로 전환된다.

> 금지: 크림 배경 + 테라코타 액센트, 블랙 + 애시드 그린, 광고 그라디언트. 흔한 AI 디폴트다.

### 5-3. 타이포그래피

| 역할 | 서체 | 이유 |
|---|---|---|
| 디스플레이 · 숫자 | **Wanted Sans** | 숫자 폭이 안정적이고 한글 완성도가 높다. 가격이 이 사이트의 주인공이므로 숫자 전용 얼굴을 따로 쓴다 |
| 본문 · UI | **Pretendard** | 명율 계승. 소형 텍스트 가독성 |

```
가격 (상세)     Wanted Sans  700  32px / -0.02em
가격 (카드)     Wanted Sans  700  20px / tabular-nums
마커 숫자       Wanted Sans  700  13px
화면 제목       Pretendard   700  20px
카드 제목       Pretendard   600  15px
본문            Pretendard   400  14px / 1.6
스펙 라벨       Pretendard   500  12px  color: --ink-40
캡션            Pretendard   400  11px
```

- 모든 숫자에 `font-variant-numeric: tabular-nums` — 리스트에서 가격 자리가 흔들리지 않게
- 가격 표기는 한국식(`4억 3,000`, `월세 500/45`). 통화기호 사용 금지
- 문장은 문장부호 최소화, 라벨은 명사구로 통일

### 5-4. 형태 · 공간

```
--radius-sm: 6px    (칩, 배지, 인풋)
--radius-md: 10px   (카드, 버튼)
--radius-lg: 16px   (바텀시트 상단, 모달)
--radius-marker: 8px 8px 8px 2px   ← 마커 전용 (§6)

spacing: 4 / 8 / 12 / 16 / 24 / 32 / 48

--shadow-float: 0 2px 12px rgba(15,28,46,.12)   지도 위 부유 요소
--shadow-sheet: 0 -4px 24px rgba(15,28,46,.14)  바텀시트
```

- 지도 위 요소는 **테두리 대신 그림자**로 띄운다 (테두리는 지도 선과 충돌)
- 지도 밖 영역은 **그림자 대신 1px 라인**으로 정리 (그림자 남용 금지)
- 터치 타깃 최소 44px

### 5-5. 시그니처 요소 — 형태로 구분하는 가격 태그 마커

지도 마커를 색이 아니라 **모양**으로 구분한다. 색은 액센트 하나만 쓰기 위해 아껴야 하고, 색맹 접근성에도 유리하다.

```
매물 유형별 마커 형태 (모두 --ink 배경, 흰 텍스트)

원룸·투룸    ┌────────┐     사각 태그, 좌하단만 각짐
             │ 500/45 │
             └───────╱

아파트·주택   ┌────────┐     사각 태그 + 하단 꼬리
             │ 4.3억  │
             └───┐┌───┘
                 ╲╱

상가·사무실   ╔════════╗     이중선 태그
             ║ 1.2억  ║
             ╚════════╝

토지         ◆ 3.5억         다이아몬드 앵커

클러스터      ●  24          원형 + 건수, 크기는 건수에 비례
```

상태 변화:
- **기본**: `--ink` 배경 / 흰 텍스트
- **hover·선택**: `--accent` 배경 + 1.08배 확대 + 그림자 강화
- **방문(본 매물)**: 배경 `--ink-40`
- **거래완료**: 취소선 + 40% 투명도

### 5-6. 모션

- 바텀시트 스냅: `cubic-bezier(.32,.72,0,1)` 340ms — 이 사이트에서 유일하게 정성을 들이는 애니메이션
- 마커 등장: 지도 재검색 시 40ms 간격 stagger fade-up (최대 20개까지만)
- 나머지는 150ms opacity/transform 정도로 절제
- `prefers-reduced-motion` 반드시 준수

### 5-7. 동영상

의뢰인이 영상을 다루는 사람이라는 점은 이 사이트의 **차별점이자 설계 제약**이다. 매물 영상은 사진 캐러셀에 끼워 넣는 부속물이 아니라 독립된 자리를 갖는다.

**촬영 형식 전제 — 세로 9:16**
블로그·릴스용으로 이미 찍고 있는 영상을 그대로 재활용할 수 있어야 한다. 가로 16:9를 강제하면 재촬영 부담이 생겨 결국 영상이 안 올라온다. 세로를 기본으로 두고 가로도 수용하는 컨테이너로 설계한다.

**노출 지점 4곳**

| 위치 | 형태 |
|---|---|
| 홈 | 세로 영상 카드 가로 스크롤 레일 (쇼츠형). 이 사이트의 첫인상을 여기서 만든다 |
| 매물 카드 | 썸네일 우상단 `▶ 0:48` 배지. 영상 있는 매물임을 목록에서 바로 인지 |
| 매물 상세 | 사진 아래 **독립 블록**. "영상으로 둘러보기" |
| 지도 마커 | 영상 보유 매물은 태그 좌측에 작은 ▶ 도트 |

**규칙**
- **자동재생 금지.** 탭해야 재생. 40~60대 모바일 데이터 환경을 고려
- 상세의 사진 캐러셀 첫 슬라이드를 영상으로 채우지 않는다. 사진은 사진대로 빠르게 훑을 수 있어야 한다
- 재생 컨트롤은 항상 보이게. 탭하면 숨는 오버레이 방식 금지
- 자막 또는 30~50자 텍스트 요약을 영상 아래 병기 (음소거 시청자·검색엔진 양쪽 대응)
- 썸네일은 영상 첫 프레임 자동 추출이 아니라 **관리자가 지정**할 수 있어야 한다

**호스팅**
자체 서버 저장은 권장하지 않는다. 트랜스코딩·대역폭 비용이 단일 VPS로 감당이 안 된다. **YouTube 일부공개(Unlisted) 업로드 후 임베드**를 기본으로 하고, 관리자 폼에는 영상 URL 입력 필드만 둔다. 플레이어 크롬은 최소화 옵션으로 브랜드 이질감을 줄인다.

### 5-8. 비회원 전용 정책이 디자인에 미치는 영향

- 헤더·푸터·탭바 어디에도 **로그인/회원가입 진입점을 두지 않는다.** 관리자는 `/admin` 직접 접근
- **관심 매물은 localStorage 기반.** 관심 목록 화면 상단에 "이 기기에만 저장됩니다" 안내 한 줄. 기기 변경 시 사라진다는 사실을 숨기지 않는다
- 문의는 **폼 + 전화 + 카카오톡** 3경로. 폼은 이름·연락처·문의내용 3필드 + 개인정보 수집 동의 체크 1개가 전부. 필드를 늘릴수록 전환이 떨어진다
- **게이팅 금지.** "회원가입하면 더 많은 매물을" 같은 장치는 이 사이트에 존재하지 않는다. 모든 매물이 처음부터 다 보인다

## 8. 매물 상세 필수 표기 (법정 요구사항)

공인중개사법 제18조의2에 따라 **인터넷 표시·광고 시 아래 항목이 화면에 반드시 보여야 한다.** 디자인 단계에서 자리를 확보해두지 않으면 나중에 레이아웃이 깨진다.

**중개사무소·개업공인중개사** (모든 페이지 푸터 + 매물 상세)
- 사무소 명칭 / 소재지 / 연락처 / 등록번호 / 개업공인중개사 성명
- ⚠️ 중개보조원 관련 정보는 표기 금지

**중개대상물** (매물 상세)

| 항목 | 표기 위치 |
|---|---|
| 소재지 | 제목 아래 (동 단위까지 공개, 상세주소 비공개) |
| 면적 | 핵심 스펙 그리드 (전용면적 필수, 공급면적 병기) |
| 가격 | 최상단, 가장 큰 타입 |
| 중개대상물 종류 / 거래형태 | 배지 |
| 해당 층 / 총 층수 | 스펙 그리드 |
| 건축물 용도 | 명시항목 표 |
| 방향 | 스펙 그리드 (기준 함께 표기: "남향(안방 기준)") |
| 방 수 / 욕실 수 | 스펙 그리드 |
| 입주가능일 | 명시항목 표 |
| 행정기관 승인일자 | 명시항목 표 |
| 주차대수 | 명시항목 표 |
| **관리비** | **별도 블록. 일반관리비 / 사용료 / 기타관리비 3구분 + 세부 비목** |

**건물유형별 층수 표기 차이** — 관리자 등록 폼과 상세 화면이 이 규칙에 맞게 분기해야 한다.

| 유형 | 층수 표기 |
|---|---|
| 단독주택 | 총 층수만 (예: `총 2층`) |
| 그 외 주택 (아파트·다세대·도시형생활주택 등) | `해당층/총층` (예: `3/3층`). 의뢰인이 원하면 `저/중/고`로 대체 가능 |
| 상가·근린생활시설 | `해당층/총층` (저·중·고 대체 불가) |

추가 UI 요구:
- **거래완료 매물은 즉시 표시 전환** — 방치 시 과태료. 목록·지도·상세 모두 거래완료 스타일 필요
- **현장 확인일자** 배지 (신뢰 신호)

## 부록. 확인이 필요한 항목

시안 요청 전에 아래를 확정하면 재작업이 줄어든다.

1. **의뢰 사무소의 주력 매물 유형** — 원룸·투룸 중심인지, 아파트 중심인지, 상가가 섞이는지. §5-5 마커 세트와 필터 구성이 여기서 갈린다
2. **의뢰인 블로그의 시각 톤** — 대표 포스트 3~5개 스크린샷 필요. 사진 색감, 반복해서 쓰는 색, 말투, 영상 촬영 스타일(세로/가로, 자막 유무)을 §5 컬러와 §7 문구 규칙에 역으로 반영해야 한다. **이 항목이 §5-2 액센트 색을 바꿀 수 있다**
3. **명율 GNB 실제 라벨** — §2-1의 계승 구조를 실제 라벨로 교체
4. **로고·CI 유무** — 없으면 워드마크를 시안에서 함께 제안
5. **서비스 지역 범위** — 지도 초기 중심 좌표와 줌 레벨, 지역 바로가기 목록에 반영
