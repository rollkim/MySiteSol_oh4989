### 변경 요약 — SPEC 수정 4건

| # | SPEC 원문 | 확정 | 근거 |
|---|---|---|---|
| 1 | MariaDB + `drizzle-orm/mysql2` | **PostgreSQL 17 + node-postgres** | 명율 스키마를 계승하지 않기로 이미 확정돼 MariaDB 명분 소멸. SPEC이 JSON 컬럼을 3곳 쓰는데 MariaDB JSON은 인덱싱 불가한 LONGTEXT. PaRaSOL과 스택 통일 |
| 2 | `sharp` 리사이즈 → 서버 저장 | **브라우저 Canvas 2종 생성 → FormData** | **명율에 sharp가 없다.** 실제는 `createImageBitmap` + Canvas + R2. 2GB 서버 메모리 경합 회피, 리눅스 바이너리 문제 소멸 |
| 3 | "명율 자동매물등록 이식" | **신규 개발** | 명율의 자동등록은 `naverScraper.ts`(Puppeteer 네이버부동산 스크래핑)이며 **본 프로젝트의 크롤링 금지와 충돌**. 텍스트 파서는 명율에 없음. 단 `server/db.ts:258`의 가격 문자열 파서는 재사용 가치 있음 |
| 4 | §3 타입 표기 | PostgreSQL 매핑 | `tinyint`→`smallint`, `json`→`jsonb`, 일시→`timestamptz` 등 |

또한 **PaRaSOL이 실제로는 Windows에서 빌드**하고 있음을 확인했다(WSL 미설치, `@next/swc-win32-x64-msvc`만 존재, 그런데도 릴리스 tar 존재). `next.config.ts` 주석의 "WSL2에서 빌드한다"는 실운용과 다르다.

### 이슈 / 특이사항

sharp 리눅스 바이너리를 Windows에서 받을 수 있는지 실측 검증함 — `npm i --os=linux --cpu=x64 --libc=glibc sharp`로 `@img/sharp-linux-x64` 획득 성공. 다만 Canvas 방식 채택으로 불필요해짐.

SPEC §3을 그대로 옮기지 않고 **검토하면서** PostgreSQL로 이식. RULE-12에 따라 발견한 문제를 우회하지 않고 수정했다.

### 변경 요약 — SPEC §3에서 고친 것

| 원문 | 변경 | 이유 |
|---|---|---|
| `lat/lng decimal(10,7)` | `double precision` | 핵심 쿼리가 bounds 검색인데 numeric은 drizzle에서 **string**으로 읽혀 마커마다 parseFloat가 돈다 |
| `property_options` PK 없음 | **복합 PK** | 같은 옵션이 중복 삽입되면 상세에 "에어컨"이 두 번 뜬다 |
| `property_images.isMain` + `sortOrder` | **isMain 제거** | 대표 사진의 진실이 두 곳이 되어 `isMain=true`인데 `sortOrder=3`인 상태가 가능. **sortOrder=0을 대표로 통일** |
| `bjdCode char(10)` | `varchar(10)` | char는 공백 패딩으로 비교·조인 사고 |
| `site_settings.key/value` | `settingKey/settingValue` | RULE-10 |

### 없어서 채운 것

- **`properties.videoSummary`** — 디자인가이드 §5-7이 요구하는 자막 요약의 저장 자리가 없었음
- **`properties.videoThumbImageId`** — §5-7 "썸네일은 관리자가 지정". `property_images`를 가리키는 순환 FK
- **`property_logs.adminUserId`** — 과태료 소명자료에 "언제"만 있고 **"누가"가 없었음**
- **`inquiries/owner_requests.privacyConsentAt`** — 개인정보 수집 동의 증빙
- **`admin_users.failedLoginCount/lockedUntil`** — `/admin`은 공개 경로라 브루트포스 노출
- 코드값 5종(문의상태·의뢰상태·로그액션·옵션21·관리비3구분) + **인덱스 10종**(부분 인덱스 3개 포함)

### 일부러 하지 않은 것

1. **거래유형별 가격 CHECK 제약** — SPEC §5가 이미 "법정 필수항목 누락 시 저장 차단"을 등록 폼 책임으로 정했고, DB에서 막으면 작성 중인 HIDDEN 매물을 저장할 수 없다
2. **`areas` 테이블** — SPEC §2에 `/areas/[slug]` 라우트가 있으나 §3에 테이블이 없음. **테이블 추가는 나중에도 비용이 거의 없어** Phase 3으로 미룸. 반대로 컬럼 변경은 데이터가 쌓이면 비싸지므로 컬럼은 지금 다 잡았음

### 이슈 / 특이사항

`Set-Content -Encoding utf8`이 PowerShell 5.1에서 **BOM을 붙여 package.json을 깨뜨림**. Write 도구로 재작성해 복구. 이후 이 프로젝트의 파일 쓰기는 BOM 없는 방식으로만 진행.

## 작업 #5 — 서버 셋업 (0~10단계)

| 항목 | 내용 |
|------|------|
| 작업 유형 | 인프라 |
| 대상 | `1.234.79.54` (카페24 가상서버, 호스트명 `ocy0027`) |

### 작업 내용

Ubuntu 24.04.4 LTS · RAM 1.9Gi · SSD 38G · **CPU 4코어** · **스왑 4GB 기존재**. 전 단계를 사용자가 직접 실행(RULE-2), Claude는 명령 작성과 외부 검증만 담당.

상세 절차와 함정 10건은 별도 문서: `계획_서버셋업(oh4989-server-setup)_20260805.md`

### 변경 요약

전용 계정 `oh4989` + SSH 키 인증 · swappiness 10 · **PostgreSQL 17.10**(PGDG) · DB/롤 + `pg_trgm` + `Asia/Seoul` · **2GB·4코어 튜닝**(shared_buffers 256MB, max_connections 30, 병렬 워커 제한) · 스키마 적용(테이블 8·FK 6·인덱스 10) · Node 22 + PM2(`User=oh4989`) · 배포 디렉토리 · **Nginx + Let's Encrypt**(HTTP→HTTPS, www→non-www **1회** 리다이렉트) · ufw(22/80/443만)

### 이슈 / 특이사항 (함정 10건 — 상세는 셋업 문서)

특히 시간을 쓴 것:
- **`sudo -u postgres psql` 실행 불가** — `/usr/bin/perl` 실행 권한이 비root에 막혀 있음(카페24 이미지 하드닝). psql 실체 바이너리 직접 호출로 우회
- **80/443이 밖에서 차단** — 서버 내부(ufw·iptables)는 깨끗한데 안 열림. **카페24 웹방화벽에서 개방 필요**. 서버 안만 봐서는 절대 안 보이는 원인
- **`pm2 startup`을 root로 실행** → `User=root` 서비스 생성. 재등록 시 `su -c` 방식은 `-u`가 빈 값이 되어 `pm2---hp.service` 생성. **root에서 `-u oh4989` 명시**로 해결
- **SSH 키 등록 실패** — `authorized_keys`가 0바이트. 파이프 방식이 빈 값을 흘림 → 공개키를 서버에서 직접 `echo`로 기록
- **채팅 복사 시 도메인이 마크다운 링크로 변환** → nginx `server_name` 깨짐. 설정은 저장소 파일로 만들어 scp

사용자 추가 조치: 카페24 웹방화벽에서 **22번을 특정 IP만 허용**. ⚠️ 배포가 22번을 쓰므로 개발 PC 공인 IP 변경 시 배포가 막힌다.

## 작업 #6 — 배포 파이프라인 · 첫 배포 (Phase 0-5)

### 작업 내용

PaRaSOL의 로컬빌드→tar→a/b 슬롯 교체 파이프라인을 oh4989용으로 이식. **서버에서 빌드하지 않는다**(RAM 2GB OOM 위험).

### 변경 요약

- `pack-release.mjs` — 허용목록 방식 선별 복사 + **반출금지 검사**(.env/.ts/.md/tsconfig 하나라도 걸리면 tar 생성 중단)
- `server-deploy.sh` — a/b 슬롯 번갈아 사용, 항상 직전 버전 1개 보존, `./deploy.sh rollback`
- **자체 확인을 `robots.txt`가 아닌 `/api/trpc/health.ping`으로** — 정적 파일만 보면 "Next는 떴는데 서버 코드가 죽은" 상태를 놓친다
- `ecosystem.config.cjs` — `max_memory_restart: 400M`(PaRaSOL 500M에서 하향, PostgreSQL과 공존), `HOSTNAME: 127.0.0.1`
- Nginx `www-data`를 `oh4989` 그룹에 추가 + 경로 750/755 조정 — **안 하면 배포 후 CSS·사진이 전부 403**

### 검증 — 첫 배포 결과

```

반출금지     ✓ 소스·env 없음
tar          10.0MB
슬롯 전환     b → a
자체 확인     health.ping 200 (1초)
외부 확인     https://oh4989.com/api/trpc/health.ping → 200
총 소요       79초
```

운영 사이트 실측: HTTPS ✅ · tRPC 왕복 `success`(Date 타입 유지) ✅ · `--ink` = `rgb(15,28,46)`(#0F1C2E, 디자인가이드 §5-2 일치) ✅ · `--accent` = `rgb(31,78,140)`(#1F4E8C) ✅ · 가격 서체 Wanted Sans ✅ · `/_next/static/*.css` 200 ✅

### 이슈 / 특이사항

- **CRLF 함정** — Windows에서 만든 `.sh`를 리눅스에 올리면 `$'\r': command not found`로 죽는다. 모든 스크립트를 LF·BOM 없음으로 작성했고 바이트 단위로 검증함
- `sharp-win32-x64` 경고는 예상된 것 — `next`의 optional 의존성이라 담기지만 `next/image`를 쓰지 않아 호출되지 않음. **sharp 도입 시 이 경고가 실제 장애가 된다**
