## Phase 1 범위

SPEC §8 Phase 1 = "프로젝트 셋업, 스키마+마이그레이션, tRPC 구조, 관리자 로그인, 매물 CRUD+이미지"
앞 셋은 Phase 0에서 끝났으므로 **남은 것은 관리자 로그인 · 매물 CRUD · 이미지**다.

완료 기준에 도달하려면 최소한 이것들이 필요하다:

1. **관리자 인증** — 세션 쿠키, bcrypt 검증, 실패 횟수·잠금(`admin_users.failedLoginCount`/`lockedUntil` 컬럼이 이미 있다). `ctx.adminUserId`를 채워 `adminProcedure`가 실제로 통과하게 만든다
2. **도메인 레이어(`src/domain`)** — 가격 파싱·한국식 포맷(`4억 3,000`·`월세 500/45`), 건물유형별 층 표기 분기(`codes.ts`의 `FLOOR_RULE_BY_BUILDING_TYPE`), 상태 전이. **화면·라우터에서 분리한다(RULE-14)**
3. **매물 CRUD tRPC** — `admin.property.create/update/updateStatus/delete`. 상태 변경(특히 `COMPLETED`)은 **반드시 `property_logs`에 기록**
4. **이미지 업로드** — 브라우저 Canvas 2종 생성 → FormData → 서버 검증·저장(`UPLOAD_DIR`). 원본 직업로드 금지
5. **관리자 등록 폼** — 건물유형별 동적 필수항목(단독주택은 해당층 숨김 등), 저장 전 법정 필수항목 검증
6. **공개 매물 상세** — 디자인가이드 §4-P3 블록 순서, §8 법정 명시항목 전부, 관리비 3구분

**참고**: 명율 `C:\_Hope\myoungyul\mysite\server\db.ts:258`의 가격 문자열 파서("15억"→150000)는 재사용 가치가 있다. 구조 참조는 `C:\_Hope\PaRaSOL\parasolv1\src\` (레이어·auth 패턴).

## 열려 있는 판단 (구현하며 정하면 되는 것)

- 세션 방식 — JWT(jose) vs DB 세션 테이블. PaRaSOL은 jose로 서명한 쿠키를 쓴다. **관리자 1~2계정 규모**임을 고려할 것
- 업로드 파일명·디렉토리 규칙 — 명율은 날짜폴더 + nanoid. `UPLOAD_DIR`은 `/home/oh4989/shared/uploads`
- 이미지 2종의 정확한 해상도 — 명율은 상세 1200×1000. 지도 마커 미리보기·목록 썸네일 용도를 고려해 정할 것
- 관리자 화면의 UI 라이브러리 — 공개면은 디자인가이드가 기준이지만 `/admin`은 규정이 없다

## 함정 (이미 겪은 것들 — 반복하지 말 것)

| | |
|---|---|
| **DB** | Claude는 DB에 접속하지 않는다. `drizzle-kit generate`까지만 하고 **SQL은 텍스트로 전달**(RULE-2) |
| **파일 쓰기** | PowerShell `Set-Content -Encoding utf8`은 **BOM을 붙인다**. Write 도구를 쓸 것 |
| **셸 스크립트** | 서버로 가는 `.sh`는 **LF 필수**. CRLF면 `$'\r': command not found` |
| **scp** | 반드시 **로컬 PC**에서 실행. 서버에서 하면 `C:`를 호스트명으로 해석 |
| **설정 파일** | 채팅으로 복사하면 도메인이 **마크다운 링크로 변환**된다. 저장소 파일로 만들어 scp |
| **배포 22번** | 카페24 웹방화벽이 22번을 **특정 IP만 허용**. 개발 PC 공인 IP가 바뀌면 배포가 timeout |
| **서버 빌드** | 절대 금지 (RAM 2GB OOM) |
